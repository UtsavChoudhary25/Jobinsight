1. Executive Summary

1.1 The Business & Industry Problem

Modern labor market intelligence is frequently hindered by two systemic shortcomings: 1. Opaque & Disconnected Compensation Dynamics: Public job boards either omit salary disclosures or present uncalibrated estimations derived from simplistic linear multipliers, ignoring multi-factor interactions between industry verticals, geographic cost-of-living tiers, and flexible work modalities. 2. Superficial "Black-Box" Dashboarding: Many recruitment analytics tools rely on static mock data or superficial AI wrappers that simulate predictive capabilities in the client-side browser rather than hosting validated statistical models.

JobInsight was designed and deployed to solve both problems. It bridges macroeconomic exploratory data analysis with production-grade machine learning. By processing 123,849 verified job postings across North America, JobInsight delivers an enterprise dashboard that pairs high-level labor demand analytics with an active, mathematically rigorous machine learning inference system.

1.2 Key Project Milestones Achieved

  • Zero-Simulation Guarantee: Every salary projection and NLP skill extraction surfaced on the live production application is generated dynamically by an active Scikit-Learn regression model and a multi-word n-gram lexical parsing engine.
  • Statistically Defensible Compensation Model: Trained, cross-validated, and benchmarked across 4 major regression architectures on 35,237 disclosed salary records, delivering a HistGradientBoostingRegressor pipeline with an $R^2$ of 0.3454 and an empirical error margin ($\text{MAE} = \$30,482$).
  • Dynamic NLP Entity Parser: Custom n-gram engine scanning 500+ technology and business tokens across 8 operational categories, complete with regular-expression extraction for degree requirements and years of professional tenure.
  • Unified Full-Stack Deployment: Seamlessly orchestrated on Vercel utilizing native Python Serverless Functions (api/index.py), delivering high-concurrency API responses with zero CORS latency and zero additional hosting infrastructure costs.

3.2 Data Cleaning & Normalization Protocol

The exploratory data engineering phase implemented an 8-stage data pipeline in Python/Pandas:

  1. Compensation Normalization: Raw postings express compensation in diverse temporal cadences (hourly, weekly, monthly, annual) and intervals (min, max, exact). All records were standardized to an annualized median USD value: $$\text{Annualized Salary} = \begin{cases} \frac{\text{min} + \text{max}}{2} \times 2080 & \text{if pay period is HOURLY} \ \frac{\text{min} + \text{max}}{2} \times 52 & \text{if pay period is WEEKLY} \ \frac{\text{min} + \text{max}}{2} \times 12 & \text{if pay period is MONTHLY} \ \frac{\text{min} + \text{max}}{2} & \text{if pay period is YEARLY} \end{cases}$$

  2. Outlier Mitigation: Raw compensation distributions exhibited extreme recording errors (e.g., placeholder entries of \$1.00 or typo figures exceeding \$10,000,000). The dataset was pruned to the 1st through 99th percentiles: $$\text{Pruned Range} = [\$130.00, \$300,808.00]$$ This yielded 35,237 pristine observations for statistical model training.

  3. Geographic Feature Engineering: Free-form text locations were resolved into standard two-letter US State codes and grouped into empirical Cost-of-Living tiers:

  4. Tier 1 (COLI $\ge 1.30$): California, New York, Washington, Massachusetts (e.g., SF Bay Area, NYC, Seattle, Boston).
  5. Tier 2 (COLI $1.05 - 1.25$): Illinois, Texas, Colorado, Georgia, Virginia.

  6. Tier 3 (COLI $< 1.05$): Midwest, Great Plains, and Southern regional markets.

  7. Categorical Standardization:

  8. formatted_experience_level: Mapped into Entry level, Associate, Mid-Senior level, Director, Executive, and Internship.
  9. formatted_work_type: Standardized to Full-time, Contract, Part-time, Temporary, and Internship.
  10. role_category: Consolidated from over 8,000 unique raw titles into 7 primary macro domains (Technology, Finance, Management, Healthcare, Sales, Operations, Retail).

4. Machine Learning Architecture: Compensation Regressor (Phase 3)

4.1 Problem Formulation

Compensation estimation is modeled as a multi-feature tabular regression problem: $$\hat{y} = f(X_{\text{role}}, X_{\text{exp}}, X_{\text{work}}, X_{\text{tier}}, X_{\text{remote}})$$ where the objective is minimizing the expected Mean Absolute Error (MAE) and Root Mean Squared Error (RMSE) against real disclosed annual salaries.

4.2 Algorithm Benchmarking & Model Selection

An 80/20 train/test split was established, isolating 28,189 training records from 7,048 hold-out evaluation records. To prevent data leakage, all preprocessing transformations were encapsulated in Scikit-Learn pipelines fit strictly on the training partition.

Four distinct model families were trained and systematically benchmarked:

4.3 Technical Rationale for HistGradientBoosting

  1. Predictive Superiority: Produced the lowest absolute error (\$30,482) and the highest explained variance ($R^2 = 0.3454$) on unseen test postings.
  2. Hyper-Compact Memory Footprint: Thanks to integer binning of continuous splits, the compiled Joblib binary is only 338 KB. By comparison, the Random Forest model required 42 MB, which would introduce severe cold-start latency in serverless environments.
  3. Inference Latency: Sub-10ms evaluation time per observation, making real-time interactive UI updates instantaneous.

4.4 Calibrated Uncertainty Bounds vs. Arbitrary Confidence Scores

Industry tools frequently output arbitrary percentage confidence figures (e.g. "94% Confidence"). JobInsight rejects misleading heuristics in favor of empirically bounded confidence intervals derived from the test-set error distribution: $$\text{Expected Lower Bound} = \max(20000, \hat{y} - 0.70 \times \text{MAE})$$ $$\text{Expected Upper Bound} = \hat{y} + 0.70 \times \text{MAE}$$ $$\text{Interval Half-Width} = 0.70 \times \$30,482 \approx \pm \$21,337$$

This guarantees that every salary projection transparently communicates the statistical variation inherent in North American job markets.

5.3 Regex Requirement Parsers

  • Educational Qualification Parser: Identifies degree requirements using boundary-delimited expressions:
  • Doctorate: \b(ph\.?d|doctorate|doctor of philosophy)\b
  • Master's: \b(master'?s|m\.s\.|msc|mba|master of science)\b
  • Bachelor's: \b(bachelor'?s|b\.s\.|bsc|b\.a\.|undergraduate)\b
  • Associate's: \b(associate'?s|associate degree)\b
  • Tenure Requirement Parser: Detects mandatory professional experience spans: \b(\d{1,2})\+?\s*(?:to|-)\s*(\d{1,2})?\s*(?:years?|yrs?)(?:\s+of)?(?:\s+experience)?\b Extracts integer values and outputs formatted requirements (e.g., 5 Years Required).

5.4 Token Statistics & Density Indicators

The engine computes objective textual statistics: $$\text{Skill Density \%} = \left( \frac{\text{Count of Unique Detected Entities}}{\text{Total Word Count in Document}} \right) \times 100$$ This provides recruiters and candidates with an immediate measure of how technical or requirement-dense a job description is.
